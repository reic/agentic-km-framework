你正在執行**專案收工**——把這次對話對某專案做的事完整落檔，讓之後任何視窗用 `/proj-resume` 都能接上。動手前理解 `project/PROJECT.md` 的「index＝狀態、status＝事件日誌」慣例。

**目標專案**：`$ARGUMENTS`

1. **定位專案**：有給 slug 用給定的；留空則用這次對話實際處理的專案（涉及多個則逐一收工或請使用者指定）。
2. **回顧這次對話**：做了什麼（哪些階段檔異動）、決定了什麼（範圍/方向取捨、使用者新回饋）、卡在哪、完成度要不要調整。
3. **追加一則新日誌**到 `3-status/<proj>-status.md`（進度日誌區最上面，不覆蓋舊的，格式依 `_templates/status.md`），並更新頂部「目前狀態」與 frontmatter `updated`。
4. **同步 `project/index-project.md`**：階段／完成度／下一步欄＋該專案概況段落，更新 `updated`。
5. **收尾**：1–2 句跟使用者確認記錄有無遺漏，並依共用慣例主動問要不要 `commit`（附建議訊息）。

**界線**：只落檔進度，不做實際產出；未完成的工作如實記在「下一步」，不要收工時硬做完。
