# 卡片範本（兩種：原子卡 / 結構筆記）

> personal-km 採卡片盒（Zettelkasten）結構。**一張卡只放一個想法**（原子化）；客觀層約 100–200 字、自成一說，讀單張就能理解概念。
> 領域導覽不靠固定資料夾，而靠**結構筆記（MOC）＋ `[[連結]]`**。本檔下半提供兩種範本。

---

## A. 原子卡範本（type: 觀點 / 經驗 / 提問 / 連結 / 消化）

```
---
title: <用你的「主張」當標題，不是主題；一卡一想法>
type: 觀點 | 經驗 | 提問 | 連結 | 消化      # 卡片類型（單選）
created: YYYY-MM-DD
status: inbox | tuning | card | archived   # 目前階段（＝所在資料夾；archived＝退役在 9-archive）
review: 穩定 | 待更新              # 你喊檢查後、命中需更新時標「待更新」
last_reviewed: YYYY-MM-DD         # 最後一次檢查日期（兼當「最後更新」，故不另設 updated）
related: []                       # 整合候選（相關卡）。連結要加引號才會生效：["[[卡名]]"]
merged_from: []                   # 若本卡由多張整合而來
superseded_by:                    # 若本卡被新概念取代
used_in: []                       # 被哪些報告/專案用過（查詢加值回指）
# tags 只用裸字、不要加 #（在 YAML 裡 # 是註解）。建議三組搭配：
#   ① 領域（必填，可多個）：筆記法 / 學習 / 思考 / 職涯 / 溝通 / 管理 / 人生 / 經濟學 / 研究法 / AI …
#   ② 立場・知識狀態（選填）：主張 / 假設 / 存疑 / 反對 / 預測 / 原則 / 經驗談
#   ③ 用途・給烹調用（選填）：可入報告 / 可決策 / 對話素材
# 注意：type 已是獨立欄位，別再放進 tags。
tags: [領域, ...]
wiki_refs: []          # 勾住一般食材（wiki 頁），加引號：["[[某wiki頁]]"]
source:                # 個人出處，可連回原檔（加引號）："[[原筆記名]]"
# ⚠️ frontmatter 內所有 [[連結]] 都要用引號包成 ["[[X]]"]，否則 YAML 會當成陣列、不變連結。
trigger: <什麼情境讓你想到這個>
---

# <主張>

## 客觀層（一般食材）
- 外部事實/方法/概念，自成一說、約 100–200 字（讀單張即懂，不依賴其他卡）。

## 我的觀點 ★（傳說食材）
- 你的判斷 / 立場 / 反對 / 延伸 / 你會怎麼用。
- ⚠️ 此節為空 = 留在 `0-inbox/`，尚不可進 `2-cards/`。

## 論述用途
- 能支撐什麼主張？適合哪種報告 / 情境。

## 演進紀錄（你的看法怎麼變）
- YYYY-MM-DD：<原本怎麼想 → 因什麼新事件/反思 → 現在怎麼想>（觀點的演進本身就是洞見）

## 連結
- [[其他原子卡]]、[[某wiki頁]]
```

> **章節名是固定的**（兩個層的標題務必照抄）：`## 客觀層（一般食材）`、`## 我的觀點 ★（傳說食材）`。批次工具靠這兩個標題辨識層別。

---

## B. 結構筆記（MOC）範本（type: 結構筆記）

> 一個領域一張 MOC，當該領域的導覽入口。**不放概念內容**，只放連結。原子卡多到一個領域裝不下時，可再切子 MOC。

```
---
title: <領域> — 領域索引（MOC）
type: 結構筆記
created: YYYY-MM-DD
status: moc
review: 穩定
last_reviewed: YYYY-MM-DD
related: []
merged_from: []
superseded_by:
used_in: []
tags: [MOC, <領域>]
wiki_refs: []
source: []
trigger:
---

# <領域> — 領域索引（MOC）

## <子主題分組>
| 原子卡 | 主張 |
|---|---|
| [[slug]] | 一句主張 |
```
