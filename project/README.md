# project — 任務與報告執行工作流

> 給「人」看的使用說明。Claude 遵循的完整規範在 [PROJECT.md](PROJECT.md)；執行中專案清單見 [index-project.md](index-project.md)。

## 這是什麼
知識庫（wiki/）負責**累積知識**；專案工作流負責**把知識用出去**。每個具體任務（要交付的報告/簡報/分析）＝一條從訂目標到結案的流水線。
**分工**：你提供交辦與判斷（目標、驗收、定稿）；Claude 跑流程簿記（萃取指引、追進度、寫草稿、回讀 wiki、格式化交付）。

## 六階段流水線（執行順序 0→1→2→3→4→9→5）
| 階段 | 你說什麼 | Claude 做的事 |
|---|---|---|
| 0️⃣ 原始 | 交辦/會議記錄放 `0-project-raw/` | 只讀，當事實基底 |
| 1️⃣ 目標 | 「幫 X 專案訂目標」 | 寫 goal：目標、範圍、驗收、里程碑 |
| 2️⃣ 指引 | 「整理撰寫指引」 | 寫 guide：怎麼做＋該參考哪些 wiki 頁 |
| 3️⃣ 進度 | 「更新 X 專案進度」 | 追加 status 日誌 |
| 4️⃣ 報告 | 「依 guide 寫報告」 | markdown 草稿；先回讀 wiki、記版本、數字帶基準 |
| 9️⃣ 成稿 | 「出 docx／簡報／定稿」 | report 轉交付物（docx/pptx），登記在 9-draft |
| 5️⃣ 結案 | 「結案」 | finish：評估＋併檔清殘留＋洞見**回填 wiki** |

## 跨視窗接續
開工先 `/proj-resume [slug]`（讀進度接上狀態，只讀不寫）；告一段落或換視窗前 `/proj-save [slug]`（落一則 status 日誌＋同步 index）。
